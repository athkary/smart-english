# 05 — خطة الأمان وحماية الأطفال | Security & Child Protection Plan

## 1. المصادقة والصلاحيات
| البند | التنفيذ |
|------|---------|
| كلمات مرور الأهل | `scrypt` (أو argon2id) مع salt عشوائي؛ حد أدنى 10 أحرف؛ فحص ضد كلمات المرور الشائعة |
| رموز الوصول | JWT موقّع (HS256 في MVP بمفتاح من Secret Manager، الانتقال لـES256 لاحقاً)، صلاحية 15 دقيقة، يحمل `sub, role, scope, parent_id` |
| رموز التحديث | قيم عشوائية 256-bit، تُخزن كـSHA-256 فقط، دوّارة، اكتشاف إعادة الاستخدام يلغي السلسلة كاملة |
| حساب الطفل | **لا** بريد ولا كلمة مرور. ولي الأمر يفتح جلسة الطفل على الجهاز؛ رمز الطفل نطاقه محدود (لا يصل لمسارات الأهل أو الاشتراكات) |
| منطقة الأهل على جهاز مشترك | PIN من 4–6 أرقام + Face ID/Touch ID (LocalAuthentication)، ومحاولات محدودة |
| تخزين الرموز على الجهاز | Keychain بخاصية `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` |
| WebSocket | تذكرة لمرة واحدة (60 ثانية) بدل وضع JWT في الرابط |

## 2. حماية المفاتيح والاتصالات
- **لا يوجد أي مفتاح API في تطبيق iOS** — يتحقق CI من ذلك بفحص نصي (`scripts/check_no_secrets.sh`) يمنع أنماط مثل `sk-ant-`.
- المفاتيح في Secret Manager للسحابة؛ محلياً في `.env` غير مرفوع (`.gitignore`).
- TLS 1.2+ فقط، HSTS، وApp Transport Security مفعّل في iOS (استثناء `localhost` في بناء Debug فقط).
- مفاتيح منفصلة لكل بيئة بحدود إنفاق.

## 3. سلوك الذكاء الاصطناعي المناسب للأطفال
طبقات متعددة (Defense in depth):
1. **موجّه النظام:** المعلم يبقى في موضوع تعلم الإنجليزية، لغة مناسبة للأطفال، لا يطلب بيانات شخصية (عنوان، مدرسة، هاتف، صور)، لا روابط، لا مواعيد خارج التطبيق، لا ادعاء بأنه إنسان.
2. **فلتر المدخلات:** تصنيف سريع لكلام الطالب (مواضيع محظورة، بيانات شخصية، مؤشرات خطر). البيانات الشخصية تُحجب من النص قبل التخزين.
3. **فلتر المخرجات:** فحص رد المعلم قبل TTS؛ عند الرفض يُستبدل برد آمن يعيد الطالب للدرس.
4. **مواضيع مقيّدة** حسب الوضع؛ ولي الأمر يستطيع تعطيل المحادثة الحرة ولعب الأدوار.
5. **مؤشرات القلق** (طفل يذكر أنه في خطر): المعلم يرد بلطف ويقترح التحدث مع شخص بالغ موثوق، ويُرسل تنبيه لولي الأمر — سياسة تُراجع مع مختص قبل الإطلاق.
6. **اختبارات Red-team** آلية (مجموعة موجّهات خطرة) تعمل في CI ضد عقل المعلم في المرحلة 3.

## 4. تقليل البيانات والخصوصية
- الطفل: اسم مستعار + سنة ميلاد + صورة رمزية مختارة من مجموعة ثابتة. لا صور حقيقية، لا موقع.
- لا تخزين دائم للصوت. النصوص بمدة احتفاظ يحددها ولي الأمر (0–365 يوماً، افتراضي 90) وتُحذف بمهمة مجدولة.
- سجلات الخادم لا تحتوي على نصوص المحادثات أو البيانات الشخصية.
- لا أدوات تتبع إعلانية، لا IDFA، لا إعلانات، لا روابط خارجية غير مقيّدة (روابط سياسة الخصوصية داخل منطقة الأهل فقط وخلف "parental gate").
- حذف كامل بيد ولي الأمر (مختبر على مستوى قاعدة البيانات بالتتابع) + تصدير البيانات.
- سجل تدقيق `audit_events` لكل إجراء خصوصية.

## 5. الامتثال (يجب مراجعته قانونياً قبل الإطلاق)
- **Apple:** إرشادات فئة الأطفال (Kids Category 1.3 و5.1.4) إن اختير إدراج التطبيق فيها، Privacy Nutrition Labels، Privacy Manifest (`PrivacyInfo.xcprivacy`)، نص استخدام الميكروفون، Parental gate.
- **COPPA** (الولايات المتحدة)، **GDPR / UK Age Appropriate Design Code** (أوروبا/بريطانيا)، **نظام حماية البيانات الشخصية PDPL** (السعودية) وما يماثله في دول الخليج ومصر — حسب أسواق الإطلاق.
- اتفاقيات معالجة بيانات (DPA) مع كل مزود (Anthropic، STT، TTS، النطق) وتفعيل عدم الاحتفاظ بالبيانات حيث يتوفر.

> لست محامياً؛ هذه قائمة بنود يجب أن يراجعها مستشار قانوني مختص قبل الإطلاق.

## 6. أمن التطبيق والبنية
- تحديد المعدّل (Redis)، حدود حجم الطلب والصوت، مهلات زمنية للمزودين.
- فحص الملكية على كل مسار (لا IDOR) — اختبارات آلية لكل مسار في المرحلة 2.
- الحاويات بمستخدم غير root، اعتماديات مثبتة الإصدارات، فحص ثغرات (pip-audit / Dependabot).
- نسخ احتياطي مشفر لقاعدة البيانات يومياً + اختبار استعادة شهري.
- تحقق خادمي من معاملات StoreKit 2 (لا ثقة في التطبيق وحده).

## 7. ما نُفّذ في المرحلة 1
- `core/security.py`: تجزئة scrypt + مقارنة زمن ثابت + توقيع/تحقق JWT + توليد refresh tokens وتجزئتها — **مع اختبارات وحدة تعمل**.
- رفض بدء الخادم في بيئة الإنتاج إذا كان `JWT_SECRET` ضعيفاً أو افتراضياً.
- ترويسات أمان HTTP + `X-Request-ID`.
- `scripts/check_no_secrets.sh` يمنع مفاتيح API داخل مجلد iOS.
